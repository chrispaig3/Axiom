# ThreadSanitizer suppressions for scripts/check-race.sh.
#
# One rule per race the language's own documents already state. Each
# rule has its reason in the comment block directly above it: the rule
# in docs/memory-model.md that states the race, why it is sound in
# practice, and what else the pattern could hide. The gate refuses a
# rule with no comment above it, fails a rule that matched nothing in
# its runs (a stale suppression), and re-runs programs without this file
# to show that every report the rule hides is the race it names.
#
# MM-PAR-12's implementation reliance. `sysWaitWordTimeout`
# (stdlib/Sys.ax) reads the word it may wait on with a plain 64-bit
# load, `memGetWord`, before it asks the kernel to wait, while other
# bindings write that word with atomics: a mutex's compare-and-swap and
# store, a channel's event counter. By MM-PAR-9 that is a data race.
# Sys.ax is compiled by the committed seed, which has no atomic
# primitive; the load's answer is advisory, the system call after it
# clobbers memory, and an aligned 64-bit load is single-copy atomic on
# x86-64 and AArch64. The pattern matches any frame of either access,
# so it would also hide a race on the timespec the same call takes from
# its own thread's arena on Linux. The gate keeps this one function out
# of line (`noinline`) in its builds, so an inlined copy cannot surface
# under a caller's name and the rule never has to name a caller.
race:^Sys*sysWaitWordTimeout
